This document serves as the official record of the backend foundation, database architecture, authentication, and portal services implemented for the PashuRaksha ecosystem.

## 1. Database Architecture & Schema

### Prisma 7 Configuration (`prisma.config.ts`)
We loaded schema path directives and configured database URLs strictly through a configuration file rather than directly in the schema, adhering to the latest Prisma 7 specifications.
* Location: [prisma.config.ts](file:///c:/Users/gnr22/pashuraksha/prisma.config.ts)

### Database Client Manager (`lib/services/db.ts`)
Created a singleton Prisma client manager utilizing Node Postgres (`pg` pool) and the `@prisma/adapter-pg` driver. This prevents port exhaustion and excessive connections during Next.js hot-reloads in local development.
* Location: [lib/services/db.ts](file:///c:/Users/gnr22/pashuraksha/lib/services/db.ts)

### PostgreSQL Database Schema (`prisma/schema.prisma`)
Formulated standard PostgreSQL models aligned with the locked domain principles:
* **No Animal Model / Mandatory Individual IDs**: Explicitly omitted individual animal records, registrations, or individual IDs.
* **`User` / `Account` / `Session` / `VerificationToken`**: Extends the standard NextAuth schema with user roles (`farmer`, `vet`, `gov`).
* **`Farmer`**: Tracks name, phone, state, district, taluka, and village. Features a unique, platform-generated `farmerId` string.
* **`LivestockProfile`**: Maintains approximate species count groupings (Cattle, Buffalo, Sheep, Goat, Poultry, Other) mapped to a farmer via composite primary keys `[farmerId, species]`.
* **`HealthCase`**: The central operational surveillance entity. Tracks reported symptoms, start date, location, case status (`PENDING`, `AI_ANALYZED`, `VET_ASSIGNED`, `VET_ASSESSED`, `RESOLVED`), and symptom photos/audio recording URLs. Unique `caseId` is generated by the system.
* **`AIAnalysis`**: Logs disease predictions as structured JSON. Enforces the locked constraints `isPreliminaryOnly = true` and logs the required medical disclaimer.
* **`VeterinaryAssessment`**: Logged by veterinarians, storing clinically confirmed diagnoses, severities, treatment plans, and additional notes. Separated from AI predictions.
* **`ReferenceCensusData`**: Read-only static census statistics used for planning denominators, preventing coupling with live operational patient cases.
* **`VaccineInventory`**: Tracks vaccine counts individually by product/type, avoiding combined shortage metrics.
* Location: [prisma/schema.prisma](file:///c:/Users/gnr22/pashuraksha/prisma/schema.prisma)

## 3. Supabase Cloud Storage Client Integration

Integrated Supabase Storage for direct symptom photo and cough/breath audio uploads:
* **SDK Manager (`lib/services/supabase.ts`)**: Singleton Supabase JavaScript client utilizing the service role key to bypass Row Level Security (RLS) for server operations.

## 4. Portal Business Services & Route Handlers

All inputs are strictly validated using Zod, and operational transactions are executed through transactional database adapter scripts.

### A. Farmer Profile & Livestock Count
* **Farmer Service**: Manages profile retrieves, updates, and creation. Generates unique system slugs (format: `FRM-YYYY-[6-CHARS]`) using a secure random hex generator. Atomically updates the `User` role to `"farmer"` inside a transaction.
* **Livestock Service**: Manages approximate species headcounts. Upserts are performed against the composite key `[farmerId, species]`.
* **API Endpoints**:
  - `GET` & `PUT` on `/api/farmer/profile`
  - `GET` & `POST` on `/api/farmer/livestock`
  - `PUT` & `DELETE` on `/api/farmer/livestock/:id` (owner-authorized updates using database IDs)

## 5. Repository Separation Architecture

We refactored the unified codebase into two independent, decoupled projects running on separate ports:

### A. Standalone Express Backend (`backend/`)
* **Framework**: Express.js server running on port `5000` with TypeScript.
* **Shared Session Lookup Middleware** ([backend/middleware/auth.ts](file:///c:/Users/gnr22/pashuraksha/backend/middleware/auth.ts)): Reads NextAuth session cookies (`authjs.session-token` or `__Secure-authjs.session-token`) or `x-session-token` header, pings the shared `Session` table in PostgreSQL, and verifies active credentials.
* **SMS Gateway Service** ([backend/lib/services/sms.ts](file:///c:/Users/gnr22/pashuraksha/backend/lib/services/sms.ts)) [NEW]: Central helper class routing OTP deliveries via Twilio, Fast2SMS bulk API, or console logs simulation.
* **Modular Routers** ([backend/routes/](file:///c:/Users/gnr22/pashuraksha/backend/routes/)):
  - `auth.ts` [NEW]: Exposes `POST /api/auth/otp/send` and `POST /api/auth/otp/verify` endpoints for 10-digit Indian mobile number signup and OTP verification.
  - `upload.ts`: Exposes signed URL generators for direct cloud media uploads.
  - `farmer.ts`: Handles profile registrations, digital Farmer ID badges, and headcount inventory updates.
  - `cases.ts`: Handles disease case reports, lists retrieval, and AI triage checks.
  - `vet.ts`: Handles cases queue and veterinary assessment updates.
  - `government.ts`: Exposes aggregated national charts and density warnings.

### B. Next.js Frontend App (`frontend/`)
* **Framework**: Next.js App Router running on port `3000` with Tailwind CSS.
* **Authentication**: Exclusively runs Auth.js v5 credentials flow, writing session tables to the shared database. Includes a dynamic Farmer registration form with OTP request inputs and auto-login hooks.
* **Direct Server Renders**: Leverages server components fetching from PostgreSQL using the shared database adapter ([frontend/lib/services/db.ts](file:///c:/Users/gnr22/pashuraksha/frontend/lib/services/db.ts)) to speed up page loads.
* **Mutations & Client Requests**: Invokes the Express API server at `http://localhost:5000/api` with `credentials: "include"` options to preserve cookie-based authorization.
